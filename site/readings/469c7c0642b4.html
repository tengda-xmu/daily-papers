认知带宽瓶颈：长时程智能体从动作规划转向模式规划

The Cognitive Bandwidth Bottleneck: Shifting Long-Horizon Agents from Planning with Actions to Planning with Schemas

Baixuan Xu, Tianshi Zheng, Zhaowei Wang, Hong Ting Tsang, Weiqi Wang, Tianqing Fang, Yangqiu Song
EMNLP 2026

论文比较长时程智能体的两种动作接口：从环境列举的具体动作中选择，或将紧凑模式实例化为命令。作者在四个文本环境及受控干扰实验中发现，长列表可能增加筛选负担，而模式接口引入实例化困难；相对优势随环境和模型变化。研究以提示长度及失败动作作为压力代理，并强调这些指标并非内部负荷的直接测量，实验结论也不能直接推广到真实部署。

研究问题

长时程智能体面对不断增长的动作空间时，需要在可直接选择的具体动作列表与需要自行生成参数的动作模式之间取舍。论文追问何时列表筛选负担超过模式实例化负担，以及这一转折如何依赖模型能力。

方法与路线

作者在四个文本环境比较两种接口，每个环境抽取100项任务，每次最多交互30步；用提示词长度和无效、重复动作近似不同压力，并在 ALFWorld 注入干扰动作，观察列表扩大后的性能变化。

创新与比较

论文将动作表示作为可扩展性变量，用认知带宽视角描述筛选与实例化之间的负担转移，并结合固定环境下的干扰注入分析转折。解读：其贡献主要是接口权衡的实验框架，而非证明存在可直接测量的认知容量。

证据与发现

作者观察到经验转折位于 ALFWorld 与 SciWorld 之间，但不同模型并非一致：GPT-4.1 的 PwS−PwA 差值分别为 -45.0 和 18.9。干扰增多时 PwA 成功率总体下降，部分模型却未在测试范围内交叉。

局限与边界

研究仅覆盖四个文本模拟器和现成模型的推理评估，不能直接证明开放世界适用性；上下文长度与失败动作只是负荷代理。多轮工具训练的作用仍是相关性假设。所提供阅读笔记未记录已核实的原文件缺项。

方向关联

解读：若将智能运维中的工具调用视为动作选择，论文提示需要同时评估候选命令筛选和参数实例化错误，这与操作可靠性有关。但现有证据来自文本模拟器，未验证工业运维、结构设计或实际设备安全效果。

后续研究建议

建议在目标运维场景构建受控任务，比较候选命令列表与参数化工具模式，分别记录任务成功、无效调用和重复操作；再测试不同列表规模与权限约束。迁移前应补充人工审核和监测，不能假定模拟器转折点适用。

阅读建议

建议关注长时程智能体接口设计与可靠性评估的读者重点阅读：论文同时给出跨环境比较、受控压力测试和失败轨迹分析，但对具体研究方向的匹配尚待确认。

Long-horizon LLM agents typically choose from an environment-enumerated list of grounded actions (Planning with Actions, PwA). While this interface reduces formatting risk, scaling the list increases screening load and can bottleneck planning. We study Planning with Schemas (PwS), which replaces action enumeration with a small set of action templates that the agent instantiates into executable actions. We introduce a cognitive-bandwidth perspective of this trade-off and quantify screening vs. instantiation pressure using context length proxy and failure actions proxy. Across four interactive environments, we identify an inflection point: PwA excels at small interfaces but degrades as action lists grow, whereas PwS becomes increasingly competitive and often superior. A distractor-injection stress test reproduces the PwA drop by enlarging the action space alone, isolating screening load and highlighting schema instantiation as the key remaining bottleneck.
